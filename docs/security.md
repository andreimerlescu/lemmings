# Security Posture & Integrated Audit Report

Lemmings handles sensitive session cookies, untrusted HTML/JSON responses from target servers, local headless Chromium processes, SMTP/S3 credentials, and a localhost Admin Portal. This document summarizes the threat model, security architecture, and all 10 findings (`SEC-01`–`SEC-10`) audited and remediated in Lemmings v2.0.

---

## Trust Boundaries & Threat Model

| Boundary | Untrusted Input / Risk | Mitigations Enforced |
| --- | --- | --- |
| **Target Origin Responses & Network Egress** | Malicious sitemaps, DNS rebinding / cloud-metadata SSRF, off-origin redirects, cookie-jar poisoning/DoS, huge or truncated bodies, XSS/Markdown injection in error dumps, secrets in error bodies. | Dial-time `discovery.SafeDialContext` (unmaps IPv4-in-IPv6 and rejects `169.254.0.0/16`, `fe80::/10` including zoned addresses, `fd00:ec2::254`, `0.0.0.0`/`::`, and multicast before dialing validated literal IPs; loopback & RFC1918 allowed); explicit `TLS 1.2+` (`MinTLSConfig()`); strict scheme/host/port `SameOrigin` checks; RFC 6265 / public-suffix scoped `InspectingJar` capped at `256` entries; `4 MiB` index & `2 MiB` visit body caps + `ErrTruncatedBody` check; fixed worker pool (`indexConcurrency = 8`); zero `innerHTML`/`outerHTML`/`document.write` in portal; strict hash-based CSP; `mdCell`/`mdFence` Markdown escaping; `secrets.ScrubText` across all extracted error bodies and JS console logs. |
| **Loopback Admin Portal & Prometheus** | DNS rebinding from external websites, cross-origin CSRF POSTs, distributed or single-IP token brute force, XSS. | Bound strictly to `127.0.0.1`; `Host` header allowlist (`localhost`/`127.0.0.1`/`::1`); HMAC-SHA256 signed random session cookies (`HttpOnly`, `SameSite=Strict`); dual-tier sliding-window auth limiter (`15/min` per remote IP extracted strictly from `r.RemoteAddr` via `net.SplitHostPort` ignoring `X-Forwarded-For`, capped at `1024` tracked IPs with expired/LRU eviction, plus a `60/min` global ceiling); Go 1.25+ `http.NewCrossOriginProtection()` + JSON `Content-Type` enforcement on all `POST` endpoints. |
| **Headless Chromium Process (CDP)** | Ambient host credentials leaking into browser renderer, remote CDP SSRF, cross-lemming/cross-domain cookie bleed, off-origin Scout capture leaks. | Strictly allowlisted `minimalBrowserEnv` (strips all host env secrets); ephemeral `0700` temp profile deleted on exit; `--remote-debugging-address=127.0.0.1` + `--remote-allow-origins=http://127.0.0.1` (no wildcard `*`); `-cdp-url` fail-closed to loopback hosts (`IsLoopbackURL`) unless `-allow-remote-cdp` is set, with `SafeDialContext` + `MinTLSConfig()` applied unconditionally to `/json/version` and `ws://`/`wss://`; `cookieDomainAllowed` validation before `Network.setCookies`; Scout off-origin redirect capture blocking; fresh incognito `BrowserContext` created and disposed per capture. |
| **Report Delivery (Local / S3 / SMTP)** | Partial/corrupt writes, path traversal / symlink escapes, S3 key traversal, SMTP CRLF header injection, plaintext TLS downgrade, secret leakage into argv/reports. | Atomic temp-file + `Sync` + `Close` + `Rename` confined inside `os.OpenRoot` (`0750`/`0640`); `validateSafeComponent` enforced on both `LocalTarget` and `S3Target`; `0600` `O_EXCL` trace files; strict CR/LF address validation; TLS 1.2+ fail-closed SMTP (`RequireTLS`); `secrets.Secret` redacting value type (`[REDACTED]`); `-smtp-pass` CLI flag removed. |

## Integrated Security Audit Findings (`SEC-01` – `SEC-10`)

| ID | Severity | Finding (v1.0) | Remediation (v2.0) | Verification |
| --- | --- | --- | --- | --- |
| `SEC-01` | High | `-smtp-pass` / `-spw` exposed SMTP passwords in process `argv` (`ps aux`) and shell history; plain `string` field risked accidental logging. | Removed `-smtp-pass`/`-spw`; added `-smtp-pass-file` (`0600` TOCTOU-safe check), `-smtp-pass-stdin`, `LEMMINGS_SMTP_PASS_FILE`, `LEMMINGS_SMTP_PASS`, and redacting `secrets.Secret` type implementing `fmt.Formatter`, `json.Marshaler`, `TextMarshaler`, and `slog.LogValuer`. | `TestSecret_RedactsInAllSinks`, `TestFromFile_PermissionsAndLoad`, `TestE2E_VersionAndNoSecretCLIFlag` |
| `SEC-02` | High | `MailTarget.buildMessage` interpolated `From`, `To`, `Cc`, and attachment filename directly into MIME headers without CR/LF validation, enabling SMTP header injection. | Validated all envelope and header addresses with `net/mail.ParseAddress` + CR/LF/NUL rejection; encoded subjects with `mime.QEncoding` after CR/LF stripping; formatted attachment headers via `mime.FormatMediaType`. | `TestMailTarget_RejectsCRLFHeaderInjection` |
| `SEC-03` | Medium | `MailTarget` silently sent plaintext email if remote SMTP did not advertise `STARTTLS`, and lacked explicit `MinVersion: tls.VersionTLS12` and dial/write timeouts. | Enforced `MinVersion: tls.VersionTLS12`, context-bounded dialing, `RequireTLS` defaulting to `true` for non-loopback SMTP hosts (`-smtp-require-tls`), and zero plaintext fallback on failed `STARTTLS`. | `TestMailTarget_RequireTLSFailsClosedOnPlaintextServer` |
| `SEC-04` | Medium | Prometheus `/metrics` bound `:port` without a loopback-only `Host` header check, exposing metrics to DNS-rebinding pages. | Bound strictly to `127.0.0.1:<port>` synchronously and wrapped handler with `localOnlyHost` returning `403 Forbidden` for non-loopback `Host` headers. | `TestPrometheusObserver_MetricsCardinalityHostGuardAndShutdown` |
| `SEC-05` | Medium | Dashboard stored raw `token` on `Swarm`, used `tokenHash` directly as the cookie value, had no login brute-force throttling, and no CSRF guard on future POST routes. | Removed raw token from `Swarm`; issued random 128-bit session IDs signed with ephemeral HMAC-SHA256 (`SameSite=Strict`, `HttpOnly`); added dual-tier per-IP (`15/min`, `1024`-IP bounded cap, `r.RemoteAddr` only) + global (`60/min`) sliding-window auth limiter (`429`); added `http.NewCrossOriginProtection()` + JSON content-type checks on `POST /api/artifacts/{id}/review` and `POST /api/finalize`. | `TestDashboard_AuthHMACRateLimitLocalOnlyAndCSRF`, `TestDashboard_AuthLimiterPerIPGlobalCeilingAndMapCap`, `TestDashboard_CSPAllowsExactlyTheInlineAssets` |
| `SEC-06` | Medium | `LocalTarget` wrote reports with raw `filepath.Join` + `os.WriteFile` (`0644`); trace file used `0644`; S3 object keys lacked component validation. | Confined `LocalTarget` writes with atomic temp-file + `Sync` + `Close` + `Rename` inside Go's `os.OpenRoot` (`0750`/`0640`), enforced `validateSafeComponent` in both `LocalTarget` and `S3Target`, and restricted `TraceWriter` to `0600` (`O_EXCL`). | `TestLocalTarget_ConfinedRootAndArtifacts`, `TestS3Target_RejectsUnsafeComponents`, `TestTraceWriter_PermissionsAndNoOverwrite` |
| `SEC-07` | Low | `BuildURLPool` spawned one goroutine per sitemap URL with a semaphore (unbounded goroutine creation on large sitemaps) and lacked explicit `http.Transport` timeouts and dial-time IP filtering. | Replaced with fixed worker pool (`indexConcurrency = 8`) over a channel and explicit `SafeDialContext`/`MinTLSConfig()`/`TLSHandshakeTimeout`/`ResponseHeaderTimeout` transport. | `TestBuildURLPool_SitemapAndBoundedConcurrency`, `TestCheckTargetAddr`, `TestSafeDialContext` |
| `SEC-08` | Low | Dashboard server and broadcaster goroutines were launched unjoined and relied on `time.Sleep(300ms)` during shutdown. | Replaced with synchronous `net.Listen`, `sync.WaitGroup`-joined server/broadcaster/watcher goroutines, and clean SSE drain channel (`closing`). | `TestDashboard_StartAndShutdownClean`, `go test -race ./...` |
| `SEC-09` | High *(new v2.0 surface)* | Spawning local Chromium via `exec.Command` inherits `os.Environ()` by default — exposing host tokens (AWS, vault, SMTP) to browser renderers rendering untrusted target pages. | Constructed an explicit `minimalBrowserEnv` allowlist (`HOME`, `TMPDIR`, `LANG`, `PATH`, plus OS display vars on Linux/Windows) — zero host secrets ever enter Chrome's environment. | `TestMinimalBrowserEnv_ExcludesHostSecrets` |
| `SEC-10` | High *(new v2.0 surface)* | Error bodies, JS console output, and session cookie jars can contain Bearer tokens, JWTs, API keys, or session IDs that must not leak into shared reports. | Implemented `secrets.ScrubText` across all extracted error bodies and JS console entries; allowlisted diagnostic response headers; marked `CookieStatus.RawValue` `json:"-"` and stripped it in `Store.SnapshotForReport`; raw cookie inspection requires explicit `-reveal-session-cookies` opt-in on authenticated localhost only. | `TestStore_CapsDedupReviewAndRedaction`, `TestScrubText_RedactsSensitiveTokens`, `TestRenderData_HybridForensicsPackagingAndSecretRedaction` |

## Secret Handling & Supply-Chain Verification

1. **SMTP passwords:** Store in a `0600` file (`chmod 600 smtp.pass`) and pass `-smtp-pass-file /path/to/smtp.pass`, or pipe via `-smtp-pass-stdin`, or set `LEMMINGS_SMTP_PASS_FILE` / `LEMMINGS_SMTP_PASS` from your secret manager.
2. **Cookie inspection:** Leave `-reveal-session-cookies` off (the default) unless actively debugging session-token corruption locally on your own workstation. Even when enabled, raw cookies are never persisted to reports.
3. **Remote CDP endpoints:** Leave `-allow-remote-cdp` off (the default) when running local Chrome or a loopback Docker sidecar (`127.0.0.1:9222`). Only enable `-allow-remote-cdp` for explicitly trusted staging networks.
4. **Supply-chain checks:** Run `make vulncheck` (`govulncheck ./...`), `make sbom` (deterministic CycloneDX 1.5 SBOM at `bin/sbom.cdx.json` via zero-dependency `scripts/generate-sbom.py`), and `make checksums` (`bin/SHA256SUMS`) before distributing release builds.
5. **Target authorization:** Only point Lemmings at origins you own or have explicit written authorization to load-test.
